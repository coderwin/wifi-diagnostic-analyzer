# Wi-Fi 장애 진단 & 패턴 분석 자동화 시스템 (Wi-Fi Sentinel)
> **Windows 및 Linux 공용 지능형 네트워크 진단 및 리포팅 솔루션**

---

## 🚀 빠른 시작 가이드 (Quick Start)

### 1. 가상환경 활성화 및 의존성 설치
```powershell
# Windows
.venv\Scripts\activate
pip install -r requirements.txt

# Linux
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. 주요 CLI 명령어 사용법
```bash
# 1) 현재 Wi-Fi 및 네트워크 상태 즉시 1회 정밀 진단
python src/main.py diagnose

# 2) 상시 백그라운드 모니터링 데몬 실행 (평상시 5초 / 장애 시 1초 고해상도 폴링)
python src/main.py monitor

# 3) 최근 5일 중 4일 오전 09:00 AP 크래시 가상 시나리오 데이터 주입 (테스트용)
python src/main.py simulate --days 5 --crash-days 4

# 4) 최근 발생한 장애 이력 및 상태 확인
python src/main.py status

# 5) 일별 진단 리포트 생성 (PDF / HTML)
python src/main.py report --daily --date 2026-09-30

# 6) 최근 기간별(7일/30일) 주기성/반복 패턴 심층 분석 리포트 생성
python src/main.py report --pattern --days 7
```

## 1. 프로젝트 개요 및 기획 배경

### 1.1 실제 장애 상황 시나리오
* **발생 시간:** 매일 오전 9시경 반복 발생
* **장애 대상:** Wi-Fi를 사용하는 모든 사용자 및 디바이스
* **네트워크 상태:**
  * 유선 LAN 연결: 정상 유지 (인터넷 사용 가능)
  * 무선 Wi-Fi 연결: 동시 다발적 연결 끊김 및 인터넷 통신 불가
* **임시 복구 조치:** 기기의 Wi-Fi를 껐다 켜거나 재연결 시 정상화
* **의심 지점:** 특정 시간대에 규칙적으로 반복되므로 단순 회선 장애가 아닌 **공유기/AP의 무선 모듈, 펌웨어 버그, 예약 스케줄(재부팅/무선 절전), 주변 무선 간섭** 등이 유력하게 의심됨.

### 1.2 만들고 싶은 프로그램
단순히 "인터넷이 끊겼다"는 다운타임 로그만 기록하는 도구가 아니라, **장애 순간의 전 계층(L1~L7) 지표를 즉각 진단하여 근본 원인을 자동으로 분석하고 주기적 패턴을 찾아내어 PDF 리포트로 발행해 주는 지능형 진단 프로그램**을 구축합니다.

## 2. 왜 필요한가? (Why)

1. **간헐적/주기적 장애의 원인 규명 어려움**
   * 장애가 발생했다가 수 분 내에 회복되거나 사용자가 재접속하면 증상이 사라져, 사후에 원인을 추적하기 어렵습니다.
   * "매일 오전 9시경"이라는 주기성을 컴퓨터가 객관적 통계 데이터로 증명해야 합니다.
2. **책임 소지 판별 (ISP 회선 vs 공유기/AP vs 클라이언트 기기)**
   * 유선 인터넷은 정상인데 Wi-Fi만 끊기는 경우, 인터넷 통신사(ISP) 회선 문제가 아니라 무선 AP/공유기 장애임을 명확히 구분할 수 있어야 합니다.
3. **공유기 제조사/네트워크 관리자/통신사 제출용 객관적 증거 확보**
   * 구두 설명만으로는 AS나 장비 교체를 받기 어렵습니다. 타임스탬프, 핑 RTT, RSSI, 게이트웨이 무응답 증거가 담긴 신뢰성 있는 문서가 필요합니다.
4. **선제적 대응 및 자동 복구 가이드 제공**
   * 단순 알림에 그치지 않고, "공유기 예약 재부팅 시간 확인", "5GHz 채널 변경 권장", "DHCP 임대 시간 확인" 등 실질적인 해결 조치 가이드를 제공합니다.

## 3. 만들 때 무엇을 고려해야 하는가? (Key Considerations)

### 3.1 크로스 플랫폼 호환성 (Windows & Linux 공용)
* **Windows 환경:**
  * `netsh wlan show interfaces` (현재 연결 BSSID, RSSI, 채널, 전송률)
  * `netsh wlan show networks mode=bssid` (주변 AP 및 채널 혼잡도)
  * Windows Event Log (`Microsoft-Windows-WLAN-AutoConfig`) 연계 감지
* **Linux 환경:**
  * `nmcli -t -f ... dev wifi` 또는 `iw dev <iface> link`
  * `/proc/net/wireless` 및 `wpa_supplicant` 상태 파싱
  * `journalctl` / `dmesg` 무선 드라이버 이벤트 모니터링
* **추상화 계층(Adapter Pattern):**
  * OS별 수집기를 분리하고, 공통 `WifiMetricsSnapshot` 데이터 모델로 변환하는 구조 설계 필요.

### 3.2 상시 백그라운드 구동 및 리소스 최적화
* **Dynamic Polling (동적 수집 주기):**
  * 평상시: 5~10초 간격으로 경량 Ping/상태 헬스체크 (CPU/배터리 영향 최소화)
  * 장애 의심/감지 시: 1초 단위 고해상도(High-Resolution) 심층 진단 모드로 자동 전환
* **OS 비동기 네트워크 이벤트 감지:**
  * 네트워크 연결 끊김 이벤트 발생 시 타이머 주기와 무관하게 즉시 인터럽트 진단 실행

### 3.3 단계별 계층 분리 진단 (Fault Tree Analysis)
장애 순간 병렬로 다음 항목을 동시 검증하여 원인 트리를 완성해야 합니다:
1. **L1/L2 (물리/링크):** Wi-Fi 신호 세기(RSSI), 링크 속도, BSSID 연결 유지 여부
2. **L3 (내부망):** 기본 게이트웨이(공유기 IP) Ping 응답 및 패킷 손실률
3. **L3 (외부망):** 공용 DNS/외부 IP (8.8.8.8, 1.1.1.1) Ping 응답
4. **L4/L7 (서비스):** 도메인 이름 풀이(DNS 쿼리) 및 HTTPS 웹 연결 성공 여부
5. **유선 비교(선택):** 유선 어댑터가 동시 연결된 경우 유선망 Ping 동시 테스트

### 3.4 데이터 저장 및 네트워크 단절 시 안정성
* 네트워크가 완전히 단절된 상태에서도 로컬 데이터베이스(`SQLite`)에 안전하게 저장되어야 함.
* 시계열 데이터 최적화 및 오래된 로그 자동 롤링/정리(Retention Policy).

### 3.5 통계적 패턴 인식 알고리즘
* 단순 시간 기록이 아닌, **시간대별 군집도(Clustering)** 계산.
* 예: 최근 N일간 장애 발생 시각의 표준편차를 구해 특정 시간대(예: 08:55 ~ 09:05) 집중도 산출.

## 4. 어떤 문서를 PDF로 변환할 수 있는가? (Convertible Reports)

| 문서 유형 | 주요 내용 | 활용 목적 |
| :--- | :--- | :--- |
| **1. 일별 장애 요약 보고서 (Daily Incident Report)** | 해당 날짜(24시간)의 네트워크 가동률, 장애 발생 시각, 지속 시간, 장애 원인 요약, 신호/핑 시계열 그래프 | 일일 네트워크 헬스체크 및 당일 장애 원인 신속 파악 |
| **2. 주기성/패턴 심층 분석 보고서 (Periodicity & Pattern Report)** | 7일/30일간의 시간대별 장애 히트맵, 요일별 발생 빈도, 특정 시각 집중도 통계, 반복 장애 원인 랭킹 | "매일 9시 발생"과 같은 스케줄형 장애의 통계적 입증 |
| **3. 단일 장애 사후 분석서 (Incident Post-Mortem)** | 특정 장애 1건에 대한 초 단위 시계열 타임라인 (09:00:00 정상 → 09:00:03 AP 응답 없음 → 09:00:45 재연결 복구) | 심층 기술 분석 및 공유기 로그 대조용 |
| **4. 통신사/제조사 제출용 장애 입증서 (Vendor/ISP Proof Report)** | 유선 정상 vs 무선 불능 대비표, 게이트웨이 RTT 손실 기록, 채널 간섭 스냅샷, 장비 교체 권고 의견서 | AS 기사 방문 시 또는 공유기 교체/환불 요청 시 공식 제출 |

## 5. 변환 시, 필요한 것은 무엇인가? (PDF Generation Requirements)

1. **HTML/CSS 기반 템플릿 엔진 (Jinja2)**
   * 보고서 레이아웃을 마크업과 스타일로 자유롭게 커스텀할 수 있는 템플릿 구조.
   * 회사 양식이나 개인 리포트 양식에 맞춘 유연한 디자인 제공.
2. **차트 및 데이터 시각화 렌더러 (Matplotlib / Seaborn / Plotly)**
   * 시간대별 핑 지연시간(RTT) 및 패킷 손실률 꺾은선 그래프
   * Wi-Fi RSSI(신호 세기) 변동 추이 차트
   * 24시간 x 7일 장애 발생 빈도 히트맵(Heatmap)
   * 인접 무선 AP 채널 분포도(2.4GHz / 5GHz 채널 점유 상태)
3. **PDF 변환 렌더링 엔진 (WeasyPrint / Playwright)**
   * **WeasyPrint (추천):** HTML5/CSS Paged Media 표준을 준수하여 A4 페이지 분할(`@page`), 머리글/바닥글, 페이지 번호(`counter(page)`), 인쇄 친화적 디자인에 가장 적합.
   * 무거운 외부 브라우저 없이 파이썬 네이티브 환경에서 고품질 벡터 PDF 렌더링 가능.
4. **국문/다국어 폰트 에셋 (Font Embedding)**
   * 리포트 내 한글 폰트 깨짐(ToFu/두부 현상) 방지를 위한 `Noto Sans KR` 등 오픈소스 CJK 웹폰트 번들링.
5. **A4 인쇄 규격 디자인 시스템**
   * 페이지 넘김 제어 (`break-inside: avoid`로 표나 차트가 페이지 중간에서 잘리지 않도록 방지).
   * 심각도별 컬러 팔레트 (정상: Green, 경고: Yellow, 위험/장애: Red).

## 6. 어떤 언어로 작업하는 것을 원하는가?, 이유는? (Language Selection)

### **선정 언어: Python (3.11+)**

### 선정 이유:
1. **압도적인 네트워크 및 시스템 진단 생태계**
   * `subprocess`, `scapy`, `psutil`, `ping3`, `socket` 등을 활용해 OS 네이티브 툴(`netsh`, `nmcli`, `iw`)을 호출하고 파싱하는 코드를 가장 빠르게 작성 가능.
2. **데이터 분석 및 시각화 라이브러리의 완성도**
   * 시간대별 주기성 분석, 평균 회귀, 군집도 분석(`pandas`, `numpy`, `scipy`) 및 리포트용 고해상도 차트 생성(`matplotlib`, `seaborn`)이 언어 차원에서 가장 완벽하게 지원됨.
3. **풍부하고 검증된 PDF 생성 파이프라인**
   * `Jinja2` + `WeasyPrint` 조합은 기업 수준의 인쇄용 PDF 리포트를 코드 몇 줄로 생성할 수 있는 최적의 스택임.
4. **Windows 및 Linux 단일 실행 파일(바이너리) 패키징 용이**
   * `PyInstaller`를 통해 파이썬이 설치되지 않은 환경에서도 Windows `.exe` 및 Linux 실행 바이너리로 손쉽게 배포 가능.

## 7. 어떤 프레임워크로 작업하는 것을 원하는가? 이유는? (Framework Selection)

### **1) 진단 엔진 및 데몬 코어: `APScheduler` + `asyncio`**
* **이유:**
  * 상시 백그라운드에서 비동기 I/O로 다중 Ping 및 DNS 질의를 동시에 처리하여 딜레이 없는 진단 수행.
  * 주기적 스케줄링(일별 리포트 자동 생성, 매시간 롤링 등)을 안정적으로 관리.

### **2) 데이터베이스 & ORM: `SQLite` + `SQLAlchemy` (또는 `Peewee`)**
* **이유:**
  * 별도의 DB 서버 설치가 필요 없는 임베디드 파일 기반 DB.
  * 네트워크 단절 상황에서도 트랜잭션 안전성 보장.
  * 시계열 로그 쿼리 및 통계 집계에 최적화.

### **3) 리포트 템플릿 & PDF 변환: `Jinja2` + `WeasyPrint`**
* **이유:**
  * 일반적인 마크다운 변환기보다 훨씬 세밀한 CSS 레이아웃 제어 가능 (그리드, 배지, 카드 UI, A4 규격 여백).
  * 파이썬 객체를 그대로 넘겨 HTML 템플릿을 채운 후 즉시 PDF로 변환하는 파이프라인 구축.

### **4) CLI 및 로컬 대시보드 인터페이스: `Typer` (CLI) + `FastAPI` (웹 대시보드 - 옵션)**
* **이유:**
  * `Typer`: `wifi-sentinel start`, `wifi-sentinel report --daily`, `wifi-sentinel diagnose` 등 직관적인 터미널 명령어 제공.
  * `FastAPI`: 필요 시 브라우저에서 실시간 상태와 그래프를 모니터링할 수 있는 로컬 웹 대시보드 확장 용이.

## 8. 장애 원인 자동 추론 룰 매트릭스 (Diagnostic Rule Engine)

프로그램이 장애 순간 수집한 지표를 종합하여 다음과 같은 결론을 도출합니다:

| 게이트웨이(공유기) | 외부 Ping | 유선 연결 | Wi-Fi 신호(RSSI) | 자동 진단 추론 결과 | 권장 조치 가이드 |
| :---: | :---: | :---: | :---: | :--- | :--- |
| **응답 없음** | 응답 없음 | **정상** | **정상 (-50dBm)** | **공유기 무선 AP 모듈 장애 / 크래시** | 공유기 무선 스케줄/재부팅 설정 점검, 펌웨어 업데이트 |
| **정상** | 응답 없음 | 응답 없음 | 정상 | **인터넷 회선(WAN/모뎀) 장애** | 통신사(ISP) 모뎀 및 외부 회선 상태 확인 |
| 응답 지연/패킷로스 | 지연/손실 | 정상 | **급감 (-80dBm 이하)** | **Wi-Fi 신호 감쇄 및 거리 문제** | 증폭기 설치, AP 위치 조정 |
| 정상 | 정상 | - | 정상 (채널 변경됨) | **AP 무선 채널 자동 변경(Auto DFS)** | 공유기 5GHz 고정 채널 설정 권장 |
| 연결 해제됨 | - | - | 탐색 불가 | **네트워크 어댑터 절전모드 / 드라이버 충돌** | OS 어댑터 전원 절약 옵션 해제 |

## 9. 다음 개발 로드맵

1. **Step 1: 환경 구성 및 기본 구조 셋업**
   * 가상환경 구성, `requirements.txt` 작성, 프로젝트 디렉토리 레이아웃 확립
2. **Step 2: OS별 Wi-Fi 수집기 (Collector) 개발**
